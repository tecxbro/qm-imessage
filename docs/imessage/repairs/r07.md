## Reproducer

A `/v1/reach` call made from a valid Photon capability with a named recipient or participant set and `files` previously followed two different resolution paths:

1. The route called `app.resolveReachTarget(...)` without a surface, so attachment preflight used the default Slack resolver.
2. The final `app.reachNow(...)` call retained `currentDestination`, so `createMessagingMethods().reachNow` selected Photon and resolved the target again.

This could authorize and stage attachments using Slack reachability before the final send selected an iMessage installation, line, and conversation. A denied Photon target could therefore provision a sandbox and transfer blobs before the final resolver rejected the send. The route also rejected a targetless current-chat Photon reaction before the existing backend could scope the supplied message ID to the capability-bound conversation.

The regression suite drives the actual `/v1/reach` route through `createServer`, uses `createApp` and its existing reach helpers, injects a real `PhotonDestinationResolver`, and observes sandbox provisioning, blob writes, resolver inputs, and queued structured destinations.

## Changed symbols

### `src/api/routes/reach.ts`

Before:

- `reachNow` trusted any capability destination whose runtime object claimed `type: "photon"`.
- The attachment preflight target omitted `ReachTarget.surface`.
- `openedAtSend` treated every `group_not_found` result as eligible for Slack group creation.
- `if (!del && !hasNamedTarget)` rejected current-chat Photon reactions.
- A valid Slack-shaped `threadTs` could reach attachment staging before final Photon rejection.

After:

- `reachNow` narrows `capability.destination` with the existing `isPhotonDestination` validator and fails closed on a malformed Photon destination.
- The attachment preflight includes `surface: "photon"` when the current capability has a valid Photon destination.
- `openedAtSend` remains available only when no Photon destination is selected.
- `currentPhotonReaction` permits only the existing targetless Photon reaction path; Slack still requires a named channel or participants.
- Photon `threadTs` is rejected as a Slack-only reference before any sandbox or blob work.
- The final `currentDestination` argument is unchanged, so `createMessagingMethods().reachNow` performs the current authoritative Photon resolution immediately before enqueueing a named send.

No `currentDestination` field was added to `ReachTarget`. The supported preflight seam remains `ReachTarget.surface`.

## Why iMessage needs this

A Photon destination is not a string channel label. It carries provider, installation, line, conversation, audience, and optional message identity. The locked Spectrum routing reference requires the owning phone when more than one dedicated line can serve a chat. The locked Advanced iMessage references likewise send attachments and reactions against explicit chat and message GUIDs. A Slack preflight cannot establish authority for those coordinates, and a raw reaction message ID cannot select a different conversation.

Native Photon replies remain outside R07. Spectrum replies wrap a provider message, while Advanced iMessage uses a chat GUID plus a `replyTo` message GUID and optional multipart index. Slack `threadTs` is not converted into either form.

## Remaining limitations

- R07 does not make the R06 capability projection or R15 resolver composition changes and cannot claim an assembled runtime until those coordinator-owned deltas land.
- Stable resolver behavior is proven to agree at preflight and final resolution. If authority changes after successful attachment preflight, the existing final resolver rejects or selects the then-current authorized destination, but the present shared interface cannot roll back already staged blobs and artifacts. The atomic revision-bound seam requested above remains coordinator-owned.
- Current-chat reactions are bound to the validated capability conversation before enqueueing. The Photon execution authority must still revalidate current audience and confirm that the message belongs to that provider, installation, line, and conversation.
- Provider credentials and an iMessage device were not used. No live message, reaction, attachment, or unsolicited outreach was sent.
- No general threading system was added. Photon requests with `threadTs` fail explicitly until an authorized native reply operation is composed elsewhere.
