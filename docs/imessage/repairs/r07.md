## Route behavior

The route validates a Photon capability destination before interpreting reach actions. A malformed or cross-conversation Photon destination fails with `403` before resolver, sandbox, blob, artifact, or delivery work.

Attachment preflight selects `ReachTarget.surface: "photon"` from that same validated capability destination. Named recipient and group requests therefore use the Photon resolver both before staging and during the existing final `reachNow()` authorization. Missing, ambiguous, mismatched, and unsupported Photon targets cannot use the Slack group-opening exception and return before sandbox provisioning or blob transfer.

Targetless current-chat Photon reactions continue through the existing backend, which scopes the message reference to the validated capability conversation. Slack keeps its named-target guard. Photon rejects Slack `threadTs` references before attachment work. The ordinary Slack recipient, channel, group, file, reaction, deletion, and thread behavior is otherwise unchanged.

## Integration requests and boundary

R06 must supply the validated structured Photon capability destination, and the coordinator must add the frozen typed `AppDeps.photonDestinations` seam and compose its real resolver. The current files still access that dependency through temporary casts because `src/api/app-types.ts` is coordinator-owned.

The current shared API authorizes named Photon reach twice: preflight returns a destination, then `app.reachNow()` resolves again immediately before enqueue. With a stable resolver, both calls receive identical canonical requests and the tests prove agreement. If authority changes after successful preflight, final authorization fails or selects the then-current destination after attachments were staged. R07 cannot make staging and enqueue revision-atomic because `ReachNowInput` has no reviewed resolved-destination/fence input and the route cannot roll back an already registered artifact through its current ports. The coordinator must adopt a revision-bound authorization seam or an enqueue path that consumes the exact preflight destination before claiming atomic no-work denial across that race.
