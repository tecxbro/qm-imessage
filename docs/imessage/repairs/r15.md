# R15 core composition integration

R15 is a coordinator integration session, not another parallel repair worktree. It depends on the reviewed R01-R14 contributions and uses their captured commits.

The integration adds one narrow `createPhotonCoreComposition()` factory. It wraps the restricted ciphertext installation store with the encrypted service adapter, constructs authorization against the existing QM `App`, run store, and delivery store, and returns one `PhotonCoreClient`. `buildApp()` registers the two Photon state migrations through the existing privileged migration pool, constructs the core only when every explicit authority dependency is supplied, and forwards that exact client to the existing server dependencies. The ordinary QM app, Slack core, agent loop, run store, delivery store, web surface, and default startup remain the existing instances.

The integration does not manufacture a canonical identity producer, Photon destination resolver, restricted runtime database credentials, or retained wrapping-key configuration. Those dependencies must be supplied by real production configuration before Photon activation. The privileged migration pool is not passed to the Photon runtime composition.

Focused evidence covers exact reuse of the existing QM objects, ciphertext-only raw installation persistence, authorized core checking, optional dependency omission, source-auth routes, and unchanged ordinary route authorization. It is local integration evidence only.
