## Reproducer

Before this repair, `startProviderIntake()` subscribed to Spectrum live messages and Advanced live plus provider catch-up streams. A prior process could durably capture an event receipt and exit before the downstream handoff. A replacement Spectrum process had no provider cursor and no way to enumerate that already captured row, so the normalized input remained durable but undiscovered.

The PostgreSQL reproducer captures envelopes, creates a replacement store backed by a new pool, and asks for recoverable rows without retaining event IDs in memory. The replacement sees the rows in bounded keyset order. Discovery itself leaves the contiguous checkpoint absent.

## Symbols and behavior

`createPhotonReceiptStore()` now returns an owned structural extension with `discoverRecoverable(query)`. The query:

- requires an exact provider, installation, and line scope;
- maps `lineId: undefined` only to the existing line-less sentinel;
- accepts canonical timestamps and limits from 1 through 128;
- returns captured receipts and processing receipts whose relational lease is present and expired at or before the injected `now`;
- excludes processing rows with a missing relational lease as unresolved legacy or corrupt state;
- orders by `captured_at, event_id`, fetches one extra row, and returns a keyset continuation only when another page exists;
- decodes every record through the existing event-receipt validator and rejects relational identity drift.

`startProviderIntake()` now runs a finite durable sweep after intake ownership and live/catch-up setup. Database discovery runs outside the serialized queue so live and catch-up events can still be captured while a page is pending. Each completed sweep restarts without a cursor. The pass stops when a sweep finds no new identities, or fails at the existing event or byte bounds. After discovery stabilizes, sequenced envelopes are ordered by provider sequence ahead of unsequenced envelopes, then every envelope re-enters the existing serialized `enqueue()` and `handoff()` boundary. A bounded session-local set suppresses overlap among durable recovery, provider catch-up, and live delivery; it retains at most the configured recovery event bound and is not durable state.

The existing terminal check remains. Handoff also refuses a currently live processing claim. A recovered envelope is handed off unchanged. Reference payloads fail explicitly with `PROVIDER_RECOVERY_REFERENCE_UNRESOLVED` because no approved resolver is present. Missing discovery support fails closed with `PROVIDER_RECEIPT_RECOVERY_UNAVAILABLE`.

Discovery never claims a receipt, invokes QM execution directly, advances a provider checkpoint, or treats capture as QM acceptance. Existing downstream claim and fence transitions remain authoritative.

## Frozen API and coordinator delta

The coordinator froze these shared names in `docs/imessage/repairs/contracts.md`: `ReceiptRecoveryCursor`, `ReceiptRecoveryQuery`, `ReceiptRecoveryPage`, and `EventReceiptStorePort.discoverRecoverable()`. Preparation commit `4fc09eb065ddd459946e72dc4c88729491acb0f9` did not publish them in coordinator-owned `plugins/photon/src/ports.ts`.

Integration must apply this exact shared delta:

1. Add the three frozen receipt-recovery interfaces to `plugins/photon/src/ports.ts` with the fields and types in the repair contract.
2. Add `discoverRecoverable(query: ReceiptRecoveryQuery): Promise<ReceiptRecoveryPage>` to `EventReceiptStorePort`.
3. Replace the private structural copies in the two R03 production files with imports of those canonical types.
4. Add the same bounded discovery behavior to the coordinator-owned shared fake in `plugins/photon/test/fixtures.ts`, or move the repair test helper there, so all existing provider-intake tests satisfy the now-required port.

Until that delta is integrated, real PostgreSQL stores expose the method at runtime, R03 intake fails closed for legacy stores, and five existing `provider.test.ts` cases fail only with `PROVIDER_RECEIPT_RECOVERY_UNAVAILABLE`. No optional production fallback was added to hide the missing dependency.
