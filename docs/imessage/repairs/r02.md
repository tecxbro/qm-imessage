## Reproducer

The existing `chatSessions.bind()` stores the first `ChatSessionBinding` for a Photon conversation. Binding the same conversation to a different QM session reaches:

```ts
return sameJson(current, binding) ? "duplicate" : "conflict";
```

That behavior remains unchanged. It protects first-bind identity, but it cannot represent an authorized WT07 request to change which existing QM session is selected for future turns.

## Repair

`createPhotonBindingStores()` exposes `readSelection()` and `compareAndSetSelection()` beside the compatible `bind()` and `find()` operations. Its `chatSessions` implementation uses the canonical `ChatSessionSelectionStorePort` from `plugins/photon/src/ports.ts`, frozen by `docs/imessage/repairs/contract.md`.

`readSelection()` returns the selected binding with its transport-owned version. `compareAndSetSelection()` locks the current row, validates the expected version and the stored project/line authority, updates only the selection record, increments `binding_version`, and returns the new selection. A missing row, stale version, invalid version, mismatched next conversation, or project/line alias returns `undefined` without creating or changing a binding.

The SQL conversation key does not include `projectId`, so the locked stored record is decoded and checked before update. `maskedAddress` is not treated as authority identity and may refresh without changing the selected conversation's authority. The operation changes no `message_bindings` or `message_binding_parts` rows; those continue to identify the QM session recorded for the original provider message.

## Coordinator-owned dependencies

The repair base already provides the canonical `ChatSessionSelection` and `ChatSessionSelectionStorePort` declarations in `plugins/photon/src/ports.ts`. R02 does not duplicate or modify those shared declarations.

The coordinator-owned `photon/state/0002` migration adds the required version column without modifying `photon/state/0001`:

```sql
ALTER TABLE qm_photon_state.chat_session_bindings
ADD COLUMN binding_version BIGINT NOT NULL DEFAULT 1
CHECK (binding_version >= 1 AND binding_version <= 9007199254740991);
```

The acceptance test applies the registered `PHOTON_STATE_MIGRATIONS` list to its unique disposable database. It does not reproduce the coordinator-owned DDL.
