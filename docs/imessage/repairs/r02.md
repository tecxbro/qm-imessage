# R02 selected-session compare-and-set

## Reproducer

The existing `chatSessions.bind()` stores the first `ChatSessionBinding` for a Photon conversation. Binding the same conversation to a different QM session reaches:

```ts
return sameJson(current, binding) ? "duplicate" : "conflict";
```

That behavior remains unchanged. It protects first-bind identity, but it cannot represent an authorized WT07 request to change which existing QM session is selected for future turns.

## Repair

`createPhotonBindingStores()` now exposes `readSelection()` and `compareAndSetSelection()` beside the compatible `bind()` and `find()` operations. The names and result contract follow `ChatSessionSelection` and `ChatSessionBindingStorePort` in `docs/imessage/repairs/contracts.md`.

`readSelection()` returns the selected binding with its transport-owned version. `compareAndSetSelection()` locks the current row, validates the expected version and the stored project/line authority, updates only the selection record, increments `binding_version`, and returns the new selection. A missing row, stale version, invalid version, mismatched next conversation, or project/line alias returns `undefined` without creating or changing a binding.

The SQL conversation key does not include `projectId`, so the locked stored record is decoded and checked before update. `maskedAddress` is not treated as authority identity. The operation changes no `message_bindings` or `message_binding_parts` rows; those continue to identify the QM session recorded for the original provider message.

## Shared deltas requested from the coordinator

Promote the frozen `ChatSessionSelection` shape and the two selection methods into `plugins/photon/src/ports.ts`, then expose the extended port through `PhotonStateStores.chatSessions` in `plugins/chassis/src/photon-state.ts` when the real producer and all fixture implementations are assembled.

Append this schema delta to the coordinator-owned `photon/state/0002` migration without modifying `photon/state/0001`:

```sql
ALTER TABLE qm_photon_state.chat_session_bindings
ADD COLUMN binding_version BIGINT NOT NULL DEFAULT 1
CHECK (binding_version >= 1 AND binding_version <= 9007199254740991);
```

The test applies that exact pending column delta to its unique disposable database after `photon/state/0001`.

## Remaining limitations

The coordinator-owned shared port, `PhotonStateStores` projection, and `photon/state/0002` migration are not changed on this branch. Session creation, QM authority checks, identity linking, and user commands remain WT07 work; this storage CAS is not permission to select a session. This branch is locally compiled and PostgreSQL-tested only. It is not integrated, activated, provider-accepted, or device-observed.
