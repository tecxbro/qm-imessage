## Adopted repair

`createPhotonLineOwnerStore` implements the canonical `PhotonLineOwnerStore` port already declared in
`plugins/photon/src/ports.ts`; it does not publish a competing type graph. Its key is exactly
`{ installationId, lineId }`, so Spectrum and Advanced modes compete for the same physical line. Claims use the
registered `qm_photon_state.line_owners` table from `photon/state/0002`, derive activity from fresh PostgreSQL time,
increment the positive safe-integer fence only on expired takeover, and retain the row on release.

The persisted expiry is normalized to millisecond precision so the canonical JavaScript timestamp returned to the
caller is also an exact generation token. Renewal and release require the complete key, owner, fence, and stored
expiry. An older claim from the same owner and fence therefore cannot renew or release a later renewal. Claim and
renewal recheck expiry after lock waits; an operation that returns after its new lease has already elapsed returns no
claim.

`createProviderLineOwnership` gives each acquisition a new owner ID, renews before the conservative local monotonic
deadline, and rejects a renewal unless it preserves the key, owner, and fence while advancing the exact expiry.
Missing, invalid, late, or failed renewal marks the lease lost and retries shutdown cleanup until it succeeds.

`createConnectionManager` requires this durable dependency. It acquires the provider-independent physical-line key
before either SDK constructor runs and fails with `PROVIDER_LINE_OWNER_MISSING` or `PROVIDER_LINE_ALREADY_OWNED`
before construction. The existing process-local set remains only a secondary duplicate guard, never a production
ownership fallback. Lease loss stops consumers and the SDK; explicit shutdown retains ownership until cleanup
succeeds. The active lease is checked before a connection is published and through every connection
`assertActive()` call.

## PostgreSQL evidence

The R14 PostgreSQL test uses the assigned `qm_cp1_r14_admin` source database only to create a uniquely named
disposable database through the central CP1 harness. It applies the exported `PHOTON_STATE_MIGRATIONS` definitions
through `applyPgMigrations`; it does not create a proposed schema or table directly. The test confirms exactly
`photon/state/0001` and `photon/state/0002` were registered, and confirms `line_owners` grants `SELECT`, `INSERT`, and
`UPDATE` to `qm_photon_adapter` while granting neither `PUBLIC` nor `qm_photon_core_link` access.

The remaining PostgreSQL cases use separate Node adapter processes to prove same-line cross-mode exclusion and
different-line independence. They also cover killed-process takeover with an incremented fence, stale claim
rejection, lock waits beyond claim and renewal expiry, exact-expiry renewal/release fencing, retained expired rows,
fence exhaustion, and database-authoritative time.
