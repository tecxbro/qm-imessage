## Reproducer and repair

The old source of ownership was the module-local symbol `localOwners` in
`plugins/photon/src/provider/connection.ts`. Its key correctly combined `installationId` and `lineId` without the
provider mode, but a JavaScript `Set` could exclude only another manager in the same adapter process. Two adapter
processes could therefore construct Spectrum and Advanced consumers for the same physical line.

An iMessage phone line is one physical Photon transport identity even when QM can reach it through two provider APIs.
If two adapter processes consume or send for that line concurrently, QM can duplicate intake, dispatch conflicting
writes, and observe incompatible cursors. One durable owner therefore has to cover both modes before either SDK is
constructed.

`createPhotonLineOwnerStore` implements the coordinator's `PhotonLineOwnerStore` contract against
`qm_photon_state.line_owners`. Claim and renewal derive expiry from PostgreSQL `clock_timestamp()`. Request timestamps
only supply a validated positive duration of at most 24 hours. Claim increments the fence only when the prior row is
expired, renewal requires an active exact owner and fence, and release expires the exact row instead of deleting it.
The acquisition query checks the returned expiry again after conflict handling so row-lock delay cannot expose an
already-expired claim. Renewal first locks the physical-line row, then evaluates fresh database time so a request
blocked past its original expiry cannot resurrect that generation.

`createProviderLineOwnership` supplies a new UUID for every acquisition, renews a 30-second lease every 10 seconds by
default, and records a conservative monotonic deadline from the start of each request. A missing or failed renewal and
a passed local deadline fail closed. Renewal and release are coordinated so shutdown cannot publish a late local
renewal. Loss cleanup retries at the renewal interval until shutdown succeeds or explicit release completes. The
wrapper rejects a changed key, owner, fence, or noncanonical expiry from the store.

`createConnectionManager` now accepts the durable owner dependency after the existing constructor dependency. It
rejects a missing owner before SDK construction, reserves the provider-independent local key as a secondary fast
guard, acquires the durable lease before constructing either SDK, renews during slow Spectrum construction, and
rechecks generation and ownership before publishing the connection. Ownership loss invalidates dispatch checks and
initiates consumer and SDK shutdown. Explicit shutdown retains the lease until consumer and SDK cleanup succeed, then
expires only that generation's claim.

## Shared API and coordinator deltas

The implemented shared API names and signatures match `docs/imessage/repairs/contracts.md`:

```ts
interface PhotonLineOwnerKey {
  installationId: string;
  lineId: string;
}

interface PhotonLineOwnerClaim {
  key: PhotonLineOwnerKey;
  ownerId: string;
  fence: number;
  leaseExpiresAt: string;
}

interface PhotonLineOwnerStore {
  claim(
    key: PhotonLineOwnerKey,
    ownerId: string,
    now: string,
    leaseExpiresAt: string,
  ): Promise<PhotonLineOwnerClaim | undefined>;
  renew(claim: PhotonLineOwnerClaim, now: string, leaseExpiresAt: string): Promise<PhotonLineOwnerClaim | undefined>;
  release(claim: PhotonLineOwnerClaim, now: string): Promise<boolean>;
}
```

The PostgreSQL cases use separate Node adapter processes with connection managers and consumers for same-line
cross-mode competition and different-line independence. They also cover expiry takeover after killing the first
process, stale renewal and release, fence exhaustion, release-without-delete, authoritative database time, claim
row-lock delay beyond the requested TTL, and renewal blocked beyond the original expiry. Provider tests cover renewal
loss, loss-cleanup retry, local expiry before an attempted multipart send, slow construction across a renewal,
constructor cleanup, consumer and SDK shutdown failures, cross-mode competition, different lines, and a missing
durable owner.

## Remaining limits

This branch is locally compiled and tested. It is not integrated or activated, and no Photon credential, provider
request, iMessage delivery, or physical-device behavior was exercised.

The PostgreSQL fence prevents later local dispatch after detected lease loss. It cannot cancel a provider request that
was already dispatched or make Photon enforce the database fence. Late results remain ambiguity and reconciliation
evidence under R04/R11. A synchronous `assertActive()` cannot replace R11's durable async check at every send seam.
The takeover test kills the stale adapter and proves its claim cannot renew or release the successor; it does not
manufacture a provider completion from that killed process. Exercising late completion after takeover requires the
coordinator-owned R11 completion and reconciliation wiring or a live provider request.

The PostgreSQL test creates the proposed table directly because the coordinator-owned `photon/state/0003` migration is
not present on this repair branch. Passing that test proves store behavior against the proposed schema, not migration
registration or production composition.
