# R16 provider composition integration

R16 is a coordinator integration session, not another parallel repair worktree. Its base is captured after the R15 composition and the final R01, R03, R04, R09, R10, R11, and R14 contributions are ancestors.

The integration resolves a scoped line credential before SDK construction, acquires one durable physical-line lease shared by Spectrum and Advanced mode, constructs one provider connection, and creates the public provider client for that connection. Outbound work reserves the R04 delivery record, acquires an exact fenced dispatch claim, attaches R11's non-enumerable in-process progress dependency, records the provider outcome with the exact claim, and fails closed when authority or durable completion is lost. The in-process callback is not serialized. The core link creates the existing source-signed client from the normalized input that owns each request.

Advanced inbound remains explicitly unavailable because the assembled public boundary has no approved live Advanced intake owner. Spectrum intake uses R03's recoverable receipt port. No placeholder identity, credential, delivery, native-feature, or view handler returns success.

The original WT04 provider tests require explicit deterministic line ownership after R14 removed the production fallback. That test-only compatibility edit is captured as a separate integration resolution depending on WT04, R11, and R14; it does not restore an in-memory production owner.

Production activation remains blocked until the host supplies a canonical identity producer, Photon destination resolver, separate restricted runtime database credentials, a retained installation wrapping-key configuration, and a source-signing secret. R06's candidate-erasure and R09's static unavailable route registration remain explicit cross-boundary blockers outside this integration session's owned production paths.
